# 微信云托管部署指引（小程序正式版通道）

> 目标：把 `server/` 打成 Docker 镜像部署到微信云托管，小程序经 `wx.cloud.callContainer` 调用，
> **免域名、免备案、免 SSL 证书**，正式版可直接提交审核。网页版继续走 Render，完全不动；
> 两端共用同一个 Neon 数据库，数据实时一致。
>
> 代码侧已全部就绪：根目录 `Dockerfile`（构建上下文 = 仓库根）、小程序 `utils/config.js` 的
> `CLOUD_ENV_ID`（留空 = 回落 `wx.request` 直连 Render，见「回滚」）。**唯一要回填的值就是环境 ID。**

## 架构

```
小程序 ──wx.cloud.callContainer──> 微信云托管（Docker 跑同一份 Express）──┐
网页   ──fetch──────────────────> Render（不变）──────────────────────┤──> 同一个 Neon / Cloudinary
```

- 不进入 `request` 合法域名的备案校验体系，mp 后台**无需配置任何服务器域名**
- callContainer 的请求会自动注入用户身份 header（`x-wx-openid` 等，当前未使用，无影响）
- 照片缩略图/原图预览直接走 Cloudinary CDN，不经过云托管流量

## 第 1 步：开通环境（约 5 分钟）

1. 打开 https://cloud.weixin.qq.com/cloudbase/price ，微信扫码登录（小程序管理员）
2. 开通**按量付费**环境（新用户赠 ¥400 资源点 / 3 个月免费额度，按我们用量前 3 个月为 0）
3. 关联小程序 AppID：`wx45e968f2b0809dde`（开通流程里选择这个小程序）
4. 记下**环境 ID**（形如 `prod-1a2b3c` 或 `xxx-1a2b3c`，控制台首页可见）——这是唯一要回填的值

## 第 2 步：创建服务（约 5 分钟）

控制台 → 云托管 → 服务列表 → 新建服务：

- 服务名：**`shanghai-map`**（须与 `miniprogram/utils/config.js` 的 `CLOUD_SERVICE_NAME` 一致）
- 创建后进入服务 → 发布管理 / 代码连续部署 → 绑定 **GitHub** → 授权并选择仓库
  `ShiyiXiao05/shanghai-map`、分支 `main`
- 构建方式：**Dockerfile**，路径 `/Dockerfile`（仓库根目录），构建上下文为仓库根
  （若控制台无 GitHub 绑定入口，见文末「备选：手动部署」）
- 推送 `main` 后自动构建部署，与现有 Render 流对齐

服务设置（创建时或之后在「服务设置」里改）：

| 设置项 | 值 | 说明 |
|---|---|---|
| 规格 | 0.25 核 / 0.5GB | 最低档，几个人用绰绰有余 |
| 最小副本数 | **0** | 无访问半小时后缩容到 0，**停止计费**；下次请求冷启动等几秒 |
| 最大副本数 | 1（或 2） | 个人使用 1 个副本足够 |
| 监听端口 | **3000** | 与 `Dockerfile` 的 `EXPOSE 3000` / Express 默认一致 |
| 健康检查 | HTTP `/api/health` | 已有端点，返回 `{"ok":true}` |
| 启动等待 | 20–30 秒 | 启动时 `store.init()` 跨境连 Neon 建表，留足余量 |

## 第 3 步：配置环境变量（约 3 分钟）

服务设置 → 环境变量，逐个添加（值从本地 `.env` 或 Render 控制台抄，两边保持一致）：

| 变量 | 必填 | 说明 |
|---|---|---|
| `NODE_ENV` | ✅ | `production` |
| `DATABASE_URL` | ✅ | Neon 连接串，与 Render 相同（两端共用一份数据） |
| `CLOUDINARY_URL` | ✅ | 图床，与 Render 相同（不配照片会存进 Neon） |
| `VAPID_PUBLIC_KEY` | 建议 | Web Push 公钥，**与 Render 相同**；小程序传照片/发留言也要广播推送 |
| `VAPID_PRIVATE_KEY` | 建议 | 同上 |
| `VAPID_SUBJECT` | 可选 | 如 `mailto:admin@example.com`，不配有默认值 |
| `AMAP_KEY` / `AMAP_SECURITY_CODE` | 可选 | 与 Render 相同（`/api/map-config` 用；小程序端不用，配上保持行为一致） |
| `MINIPROGRAM_APPID` | 建议 | 登录署名功能：mp 后台 → 开发管理 → 开发设置 |
| `MINIPROGRAM_SECRET` | 建议 | 同上；不配则登录停用、写接口退回客户端昵称 |
| `AUTH_SECRET` | 建议 | token HMAC 密钥，**必须与 Render 侧一致**（同一密钥双后端互验 token） |

> 敏感值只存在控制台，不进仓库（`.dockerignore` 与 `.gitignore` 都已排除 `.env*`）。

## 第 4 步：回填环境 ID 并联调（我来做）

1. 把环境 ID 填进 `miniprogram/utils/config.js` 的 `CLOUD_ENV_ID = ''`
2. 微信开发者工具重新编译：所有请求自动改走 callContainer
   （无需勾选「不校验合法域名」，与域名校验体系无关）
3. 回归清单：冷启动进公共广场 → 加入地图（D3JS39 → 51 地点）→ 加/编/删地点（回收站）→
   打卡、想去 → 传照片与预览（Cloudinary 直链）→ 行程单 → 留言 → 登录署名
4. 控制台「服务 → 日志」确认请求到达、无报错

## 第 5 步：发布正式版（你在 mp 后台操作）

1. 开发者工具「上传」→ mp 后台设为**体验版** → 真机按上面清单回归
2. mp 后台「开发管理 → 服务器域名」：**什么都不用配**
3. 直接「提交审核」（类目建议：工具 > 信息查询，或按首次审核意见调整）
4. 审核通过（通常 1–7 天）→「发布」——正式版入口干净：免扫码、免开调试

## 成本

- 前 3 个月：免费额度覆盖，¥0
- 之后：最小副本 0 + 每天几十次请求 ≈ **每月几毛钱**（CPU 0.055 元/核时 + 内存 0.032 元/GB时，精确到 100ms）
- 照片走 Cloudinary CDN，不产生云托管出流量费
- 按量计费需账户有余额，**充 ¥10 够用一年**；介意冷启动可改常驻 1 副本（约 ¥21/月）
- 2026-04-23 起免费额度政策有调整，开通时以 https://cloud.weixin.qq.com/cloudbase/price 为准

## 回滚

小程序 `utils/config.js` 把 `CLOUD_ENV_ID` 清空 → 全部请求回落 `wx.request` 直连
`BASE_URL`（Render；体验版需开调试模式）。服务端改动全部向后兼容，Render 行为不变。

## 备选：手动部署（控制台无 GitHub 绑定入口时）

1. 本地构建：`docker build -t shanghai-map . `（国内网络拉 `node:20-alpine`
   可用镜像加速前缀，如 `docker pull docker.1ms.run/library/node:20-alpine` 后重新打标签）
2. 用微信云托管 CLI 发布：`npx @wxcloud/cli` 按提示扫码登录后执行部署
   （CLI 文档：https://cloud.weixin.qq.com/cli/ ，支持 `wxcloud deploy docker`）
3. 或控制台「服务 → 发布 → 镜像上传」直接推镜像 / 用代码压缩包部署（Dockerfile 方式）

## 常见问题

- **首次请求慢几秒**：副本从 0 拉起（冷启动），个人使用可接受
- **callContainer 报 env/service 错误**：检查环境 ID 与服务名是否和控制台完全一致
- **容器起来了但接口 500**：看服务日志；多半是环境变量漏配（`DATABASE_URL` 缺失会启动即退出）
- **token 失效（401）**：两侧 `AUTH_SECRET` 不一致，或未配置（进程内随机密钥重启即变）
