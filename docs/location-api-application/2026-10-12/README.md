# wx.getLocation 申请材料（2026-10-12 第三次）

前两次被拒原因：**「使用场景未符合开放范围」**。核对结论：`wx.getLocation` 官方文档的国内主体开放列表**包含**「工具 > 信息查询」，
说明类目本身可能在范围内，但审核对"业务必须性/真实性"的判定更严；也可能是**主体为个人**带来的限制。

## 这次的三点变化

1. **小程序已上线（正式版）**：不再是"开发中的功能"，有真实使用场景；截图/录屏都来自线上版本。
2. **建议改类目**：应用内容其实是"上海景点/餐饮/展馆的游玩地图"，
   改到 **「旅游服务 > 景点/旅游」**（或「生活服务」）比「工具 > 信息查询」更贴合业务，
   也更容易落在地理位置接口的开放范围内。类目变更后重新提交本申请。
3. **补充 30 秒录屏**（上次只有截图，且是开发者工具 + 模拟定位）：
   分镜如下，建议用**真机 + 真实位置**录制；若暂时无法真机授权，用开发者工具并**在画面中注明"模拟定位"**，不要伪装成真机。

## 申请理由（复制对应版本到后台，≤300 字）

- 已改/打算改类目为旅游服务 → `application-reason-travel.txt`
- 保持「工具 > 信息查询」 → `application-reason-tool.txt`

## 30 秒录屏分镜

| 时间 | 画面 | 要点 |
|---|---|---|
| 0–5s | 打开小程序首页，地图上已有若干标记 | 展示真实业务：共享地图 + 分类标记 |
| 5–10s | 点击「◎ 附近」 | 明确是**用户主动点击**触发 |
| 10–16s | 出现隐私指引 / 位置授权弹窗 → 点允许 | 证明有授权流程，不是静默获取 |
| 16–24s | 展示"离我最近"列表：5 个地点 + 直线距离，由近到远 | 证明位置是排序的必要依据 |
| 24–30s | 点开其中一个地点详情 | 证明定位服务于真实使用闭环 |

## 需要准备/确认的材料

- [ ] 3–4 张线上截图：首页（含「附近」入口）、附近结果页、地点详情、隐私指引中"收集你的位置信息"那一条
- [ ] 30 秒录屏（mp4，≤20MB）
- [ ] 隐私保护指引已勾选「收集你的位置信息」，用途：`按当前位置排序附近地点（仅在本机计算，不上传服务器）`
- [ ] 申请文案里**不要**出现"导航""签到打卡""配送""景区经营"等与当前实现不符的场景（前两次被拒的常见雷区）
