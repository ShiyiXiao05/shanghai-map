# wx.getLocation 拒绝后的核对记录

核对日期：2026-10-10。

## 已确认的事实

- 微信公众平台「账号设置 → 基本设置」显示当前服务类目为「工具 → 信息查询」，主体为个人。
- [wx.getLocation 官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.getLocation.html)的国内主体开放列表包含「工具 → 信息查询」，对应与地理位置相关的服务。文档并未写明所有个人主体均禁止申请。
- 拒绝通知指出「所描述的接口使用场景」未符合开放范围，未给出更细的判定理由。类目进入开放列表不等于任意定位用途都能获批；也不能据此确定只是申请文案的问题。
- 现有实现由首页点击「附近」触发，获取手机当前位置，在客户端计算当前地图内地点的直线距离并展示最近 5 个地点。拒绝授权或定位失败时不改用地图中心。位置未在该调用链中上传服务器，也无后台持续定位或轨迹记录。
- 「去过」按钮目前是手动修改状态，并非按 GPS 校验到场；详情页高德按钮复制链接，尚未调用 wx.openLocation。因此申请中不应将它们描述为基于位置的签到或已实现的微信内导航。

## 本次准备

`application-reason-revised.txt` 按实际已实现的「当前位置附近地点信息查询」重写，保留原申请理由供回溯。这份修改理由尚未填入后台，也未重新提交。

现有两张图片来自微信开发者工具，第二张使用注明的上海市中心模拟定位。它们能展示入口和排序结果，但不包含真机隐私指引、位置授权及完整操作流程。

建议重新申请时补充实际运行的短录屏：进入地图 → 点击附近 → 展示隐私/位置授权（如当次出现）→ 显示最近 5 个地点及直线距离 → 打开一个地点的详情。按实际运行环境注明真机或开发者工具及是否模拟定位；无需展示个人真实坐标、家庭或其他敏感地点。申请页视频为选填，支持 MP4、最多 1 个、不超过 20 MB。

建议先按当前「工具 → 信息查询」类目提交真实场景的材料。如果仍以开放范围拒绝，应向微信官方咨询该类目下「当前位置到共享地图内地点的距离查询及排序」是否允许，附上拒绝通知和演示材料。不能保证更换文案即可获批，也不应为审核虚构配送、景区经营或 GPS 签到业务。

## 备选接口的边界

[wx.getFuzzyLocation 官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.getFuzzyLocation.html)将开放条件描述为「具备与地理位置强相关的使用场景」，同样需要后台申请和 app.json 声明。它返回模糊地理位置；若改用该接口，仍基于手机当前位置，但附近距离和排序的精确程度会降低，需同步调整界面说明。文档未承诺该项目必然通过，也未给出固定误差范围。本次没有更换接口或修改定位代码。
