# Android 性能与更新验证

日期：2026-10-08。本文记录 0.3.0 发布前的性能排查和 0.2.0 在线更新验证。最终发布信息见 `Android-0.3.0发布说明.md`。

## 响应速度问题与修改

| 操作 | 原请求链路 | 调整后 |
| --- | --- | --- |
| 想去/点赞、公开切换 | 写操作 → 整图 GET → 照片 GET → 留言 GET | 使用写操作返回的结果，只需一个请求（详情本身有未完成读取时会补加载） |
| 打卡 | 写操作 → 整图 GET → 重载详情 | 使用服务端返回的打卡状态及时间，不重载整图 |
| 保存地点 | 写操作 → 整图 GET → 重载详情 | 合并写操作返回的地点数据，保留照片/留言计数和 wishes |
| 新增留言 | 写操作 → 留言 GET → 整图 GET → 再加载照片/留言 | 直接追加服务端返回的留言并更新本地计数 |
| 删除留言、删除照片 | 写操作 → 整图 GET → 重载照片/留言 | 本地移除对应项并更新计数 |
| 上传照片 | 上传 → 照片 GET → 整图 GET → 重载详情 | 保留上传与照片 GET，去掉无关重载 |
| 首页/加入地图 | 地图信息 GET → 地点 GET | 两个独立读取并行 |
| 进入详情 | 照片 GET → 留言 GET | 两个独立读取并行 |
| 地图标记刷新 | 点赞/计数变化也清空并重建全部标记 | 仅标记字段、选择或主题变化时重绘 |

所有本地更新在服务端成功响应后执行，失败不显示虚假的成功状态。写请求仍禁止自动重发，避免切换类操作被执行两次。回归覆盖点赞响应同步和只发一个请求。

独立审查发现并修复：打卡时间应使用服务端响应；写操作期间阻止详情重试读取旧数据覆盖新留言；成功更新地点时失效旧的首页加载响应。

## 服务端延迟观察

本机对线上只读接口的采样：健康检查约 0.77 秒，公共地点列表两次约 3.22、3.34 秒。包含网络传输和代理等开销，不能把这些数值视为手机上的精确耗时，也不能据此单独判断 Render 冷启动。

代码检查发现服务端地点列表已对照片/留言/想去统计使用批量查询并行，不是逐地点 N+1 查询。本轮没有修改后端或数据库。若客户端去除冗余请求后仍慢，应请部署人员检查：

1. Render 请求日志和实例冷启动情况。
2. 数据库查询耗时、连接建立耗时及 Render/数据库地域。
3. 写请求中的权限校验、数据库事务和文本审核耗时。
4. 分别记录服务端请求时间和手机端请求时间，区分网络与数据库瓶颈。

不缩短写请求超时来伪装加速，也不建议对点赞/公开切换自动重试。当前读取接口的网络失败最多重试一次，网络故障时仍可能产生较长等待。

## 本轮交互修改

- 地图/地点之间增加垂直拖动分隔条，比例限制为 25%–70%，保存页面恢复时的比例，支持无障碍比例调整。
- 地图标记改为简洁的水滴定位针与白色中心点，保留深橙色美食、白色轮廓、深色描边和已去过角标。
- 随机抽签使用约 2.4 秒滚轮减速动画，停下后才开放查看地点/再抽一次，预先选择随机结果并确保滚轮落到对应项。
- 已检查模拟器拖动后的布局和滚轮停止截图；地图实际视觉效果仍需手机测试。

## Render 更新链路验证

线上更新清单已返回 HTTP 200，JSON 为 `com.modu.explore` / `versionCode=2` / `0.2.0`。响应含 `Cache-Control: no-cache`。

已完整下载约 73 MB 的线上 APK，SHA-256：

```text
be92c6f47a8eec0f9ba2492e630add1fab4d102e610440f2b1ebfa6c77bdca6a
```

与清单一致，APK 签名验证通过，SHA1 与当前调试包一致。服务器清单和下载链路正常。

已通过 Android 模拟器中的真实「我的地图 → 检查更新」入口连接线上 Render，成功显示“当前已是最新版本”，没有错误。这符合已安装与线上均为 0.2.0 的情况，不会出现下载按钮。完整应用内升级流程还需发布更高版本且保持相同签名，再验证下载、系统安装授权、覆盖安装和数据保留；不能只把清单版本改高来测试，否则会被 APK 版本校验拒绝。

排查阶段的测试构建没有替换 `public/android/` 发布文件。后续用户授权发布 0.3.0，沪娘图标与上述改进一并进入该发布包。

最终验证：14 项 JVM 单元测试、7 项 Android 15 模拟器回归测试通过，lint 无错误；拖动布局与滚轮停止界面已截图检查。
