## 2. P0 修复

### 2.1 小程序照片上传（F-50）——本轮最关键的功能修复

**根因**：小程序端 `pages/detail/detail.js` 把原图转 base64 后**同时**作为 `full` 和 `thumb` 发送，且不做任何压缩；而三条通道的限制互相矛盾：云托管 `callContainer` 请求上限 **100K**（官方明确"请求中不建议包含图片"）、Render 通道 `express.json` 3MB、服务端 `thumb ≤150KB`。普通手机照片在这三条路里**没有一条能走通**。

**修复**（4 处协同）：
1. 新增 `miniprogram/utils/image.js`：`compressToLimit()` 用 `wx.compressImage` 按"先降质量、再降宽度"迭代到目标体积，`fileToDataUrl()` 统一转 data URL，所有分支保证 settle（不会卡死）。
2. 服务端新增 `GET /api/upload-config`（`server/app.js:48`）下发 `{cdn, maxFullBytes, maxThumbBytes}`；`MAX_THUMB_BYTES` 由 150KB 收紧到 **64KB**。
3. `pages/detail/detail.js:246-291`：按预算压缩——`总预算 92KB`（对 100K 的上限留余量），`cdn=true` 只传 `full`；`cdn=false` 时额外生成 ≤20KB 的缩略图；上传前本地自检，超限给中文提示而不是等服务端 400。
4. 服务端 `thumb` 改为**可选**（缺失时回落用原图，老客户端不会因此 400）。

**验证**：`fix-verification-results.json` → 小程序侧 `cdnModeBodyBytes=40 994`、`dbModeBodyBytes=54 340`（均 < 100K）；端到端 `E2E-04` 服务端实收请求体 **69 720 B** 且 201；`E2E-14` CDN 模式只传 full 即成功并返回 CDN 缩略图。

### 2.2 云托管"单通道"可用性（F-01，部分修复）

**根因**：`CLOUD_ENV_ID` 已配置 ⇒ 全部请求走 `callContainer`，代码里**没有任何运行时降级或重试**；而 Render 域名无法 ICP 备案，回落通道在真机不可用。

**已修**：请求加 15s 超时、幂等 GET 网络失败自动重试 1 次、登录过期恢复改为"先登录成功再覆盖 token"（`utils/auth.js`）、服务端加温和限流避免被刷。

**仍需人工确认**（我无法从外部探测）：云托管服务是否真的部署成功、`minNum: 0` 的冷启动是否需要调成 1。见第 8 节清单第 1–3 条。

## 3. 合规修复

### 3.1 UGC 内容安全（F-02）——已实现

**根因**：全仓 `msgSecCheck`/`mediaCheckAsync` 零命中，而"公共广场"是**全网可见**的公开 UGC。

**修复**：新增 `server/content-security.js`
- `createContentSecurity()`：`stable_token` 获取并缓存 `access_token`（提前 5 分钟刷新），调用 `security.msgSecCheck` v2；
- 写入前拦截：地点 `name/description/address/tags`（`routes/places.js` 新增与编辑两处）、留言 `body`（`routes/comments.js`）、昵称（`routes/auth.js`）；
- **降级策略**：未配置 AppID/Secret → 整体停用；微信接口报错/超时 → 放行并记日志（可用性优先）；只有明确违规（`errcode 87014` 或 `suggest !== pass`）才 400 且不入库；`CONTENT_SECURITY=off` 可临时整体关闭。

**验证**：4 个新测试（通过/命中违规不入库/接口故障放行/未配置零外部请求）全绿。

**未覆盖**：图片 UGC 需 `mediaCheckAsync` 异步审核（依赖可公网访问的图片地址与回调处置），已在模块注释里写明方案，列为下一步。

### 3.2 图片内容安全（F-02 剩余部分）——已实现

- `content-security.js` 增加 `mediaCheckAsync()`：上传后把照片送审（有图床时用 CDN 直链，否则用 `{PUBLIC_BASE_URL}/api/photos/:id?map=<码>`），成功则把照片标记为 `pending` 并记录 `trace_id`。
- 回调 `POST /api/wechat/media-check-callback`：校验 mp 后台「消息推送」Token 的 `sha1` 签名（`timingSafeEqual`），按 `suggest` 把照片置为 `pass`/`risky`；**只有明确 pass 才放行，review/risky 一律先隐藏**。
- 违规照片会被所有读取路径过滤：照片列表、回忆时间线、地点照片计数、公共广场、单张取图（`store.js` 中 `moderation <> 'risky'`）。
- 未配置 `WECHAT_MSG_TOKEN` 时不送审（没有回调通道，送审没有意义），上传行为完全不变。

### 3.3 举报入口与处置（F-03）——已实现

- **接口**：`POST /api/reports`（提交）、`GET /api/reports?map=码`（owner 查看待处理）、`POST /api/reports/:id/resolve`（结单）；
- **权限模型**：带邀请码可举报本地图任意内容；不带邀请码时**只能举报公开可见内容**（拿 id 探测私有内容返回 404）；
- **防刷**：单 IP 10 分钟 10 次；
- **通知**：写结构化日志（Render/云托管日志可见），配置 `REPORT_WEBHOOK` 后同时推到企业微信机器人；
- **两端入口**：小程序详情页「举报该内容」→ 原生 ActionSheet 选择原因；网页详情弹层「举报该内容」→ 独立弹层（原因 + 补充说明）。
- 创建者处置目前通过 API/日志完成（两个端点都要求有效邀请码），管理后台 UI 列为后续项。

### 3.4 隐私授权（F-04）——提审时填写，代码侧无需改动

代码侧无需改动（`app.json` 的 `requiredPrivateInfos` 与实际调用一致）。

**入口位置说明（实测更正）**：mp 后台「账号设置 → 服务内容声明 → 用户隐私保护指引」**只对已发布上线的小程序显示**；本项目尚处体验版阶段，后台里找不到是正常的，**不是认证问题**。
未发布阶段的唯一入口是：**「版本管理」→ 提交审核 → 页面底部「用户隐私保护指引设置」→ 选择「采集用户隐私」并逐项填写用途**，审核通过且发布上线后生效。

需要声明的类型：位置信息（getLocation）、**选择的位置信息**（chooseLocation，易漏）、选中的照片/视频（chooseMedia）、相册仅写入（saveImageToPhotosAlbum）、剪切板（getClipboardData）。

| `app.json` | 摘掉 `requiredPrivateInfos` 与 `permission.scope.userLocation`（当前无调用，留着反而核验不符） |
| `pages/search` | 原生选点不可用时进入**地图手动点选**模式（内嵌 `<map>` 读点击坐标）；新增可编辑的「名称」输入框（点选模式必须手填） |
| `pages/index` | 「附近」在无权限时按**地图当前中心点**近似排序并明确提示，抽成 `showNearby(location, approximate)` |

**影响**：提审不再被 61040 拦截，未授权用户也能添加地点；代价是"附近"精度取决于地图中心，选点需手填名称。

**恢复路径**：微信认证通过 → 「接口设置」申请到权限 → 隐私指引补勾位置类型 → `LOCATION_API_ENABLED = true` 并恢复 app.json 两处声明。

### 12.4 用户反馈整改（2026-10-11）

| # | 反馈 | 根因 | 处理 |
|---|---|---|---|
| 1 | 景点标记的 emoji 会超出圆形标记且错位 | canvas 生成图标时按固定 `22px` 画 emoji，而 emoji 字形普遍大于字号（彩色字体还会外扩），画在半径 17 的圆里必然溢出；`textBaseline='middle'` 对 emoji 也不等于视觉居中（各平台字体度量不同） | 按圆内可用直径（25px）收敛字号 → 用 `measureText().width` 二次收敛（宽 emoji/组合 emoji）→ 用 `actualBoundingBoxAscent/Descent` 按真实墨迹居中，取不到时退回少量像素补偿。对比图：[docs/assets/2026-10-11-marker-emoji-fix.png](../assets/2026-10-11-marker-emoji-fix.png) |
| 2 | 添加地点只能地图点选，希望支持按名字搜索 | 小程序端没有可用的地图 key，服务端虽有 `AMAP_KEY` 但没有对外暴露搜索接口 | 新增服务端代理 `GET /api/geo/search`（高德 Web 服务关键字搜索，5s 超时、5 分钟内存缓存、单 IP 每分钟 30 次限流），小程序「添加地点」页加搜索框与结果列表；key 只留服务端，小程序不需要配置、也不用加请求域名 |
| 3 | 「附近」功能太复杂，只要按当前位置定位 | 之前为了绕开被拒的地理位置接口权限，做了"常用地标/地图中心/地图点选/粘贴高德链接"四级手动兜底 | 全链路删除，只保留"自动定位"（地图组件能力）：成功按当前位置排序并显示定位点；不可用给明确提示；用户拒绝过授权时引导去设置页。连带删除 `utils/location.js` 与 `config.NEARBY_ANCHORS` |

**关于"可被搜索 / 可被分享"**：产品确认**需要**这两项能力，因此**不做任何限制**——`miniprogram/sitemap.json` 保持 `allow`（利于搜一搜收录），`onShareAppMessage`/`onShareTimeline` 保持实现（可转发、可分享朋友圈）。只需在 mp 后台确认【设置 → 基本设置 → 隐私与安全 → 允许被搜索】处于开启状态，并在发布后用另一个微信号实测一次搜索与转发。
